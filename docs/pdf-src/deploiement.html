1 En bref

git clone <dépôt> sentinel-x && cd sentinel-x
docker compose up -d --build

Cette seule commande, sans fichier de configuration, déploie la plateforme complète :

  • une autorité de certification locale et un certificat TLS par service ;
  • tous les secrets : clé de session, jeton du service IA, mots de passe MQTT, mot de passe du premier administrateur ;
  • le dashboard en HTTPS (le HTTP redirige vers HTTPS), le backend, le broker MQTT, le service IA et la passerelle USB du boîtier ;
  • le compte administrateur initial, créé au premier démarrage.

Aucune donnée sensible n'est stockée dans le dépôt ni dans un fichier à compléter. Relancer la commande conserve la CA et les secrets existants ; les certificats sont renouvelés automatiquement 30 jours avant leur expiration.

3 Prérequis

  • Serveur : Raspberry Pi 5 (4 Go de RAM minimum) sous Raspberry Pi OS 64 bits, ou PC Linux 64 bits (Debian 12, Ubuntu 22.04 ou plus récent).
  • Espace disque : 10 Go libres (l'image IA pèse environ 2,7 Go).
  • Docker Engine 24 ou plus récent, avec le plugin docker compose.
  • Internet pour la première construction uniquement : dépendances et modèles (YOLOv8n, YuNet, SFace) sont téléchargés puis vérifiés par empreinte SHA-256. Ensuite, la plateforme fonctionne hors ligne.
  • Le boîtier ESP8266 flashé avec le firmware du dépôt (voir le guide du firmware) et, pour la vision, une webcam USB.

curl -fsSL https://get.docker.com | sh

4 Déployer

  1. Récupérer le projet sur le serveur : 
    git clone <url-du-dépôt> /opt/sentinel-x
cd /opt/sentinel-x
  2. Déclarer l'adresse du serveur (recommandé) : pour accéder au dashboard depuis les autres postes de la table, indiquez son adresse IP ou son nom. Elle sera incluse dans le certificat HTTPS : 
    echo "PUBLIC_HOSTS=192.168.10.1" > .env
    Sans cette étape, le dashboard n'est accessible que depuis le serveur lui-même (https://localhost).
  3. Lancer la plateforme. La première construction dure de 10 à 30 minutes selon la connexion et le matériel : 
    docker compose up -d --build
  4. Vérifier que tous les services sont démarrés et sains : 
    docker compose ps
    init doit être Exited (0) ; frontend, backend et ai doivent être healthy ; mosquitto et bridge, Up.

Les services redémarrent automatiquement après une coupure de courant ou un redémarrage du serveur (restart: unless-stopped), à condition que Docker démarre avec le système (sudo systemctl enable docker).

5 Premier accès

5.1 Faire confiance au certificat

Les certificats sont signés par une autorité locale créée au premier démarrage. Le certificat public de cette autorité est exporté dans deploy/runtime/sentinel-x-ca.crt. Installez-le sur chaque poste qui consultera le dashboard ; sinon, le navigateur affichera un avertissement de sécurité.

SystèmeInstallation de sentinel-x-ca.crt
WindowsDouble-clic → Installer le certificat → Ordinateur local → « Autorités de certification racines de confiance »
macOSDouble-clic → Trousseau Système → ouvrir le certificat → Se fier : « Toujours approuver »
Linux (Chrome)Paramètres → Confidentialité et sécurité → Gérer les certificats → Autorités → Importer
Firefox (tous systèmes)Paramètres → Vie privée et sécurité → Certificats → Autorités → Importer
AndroidParamètres → Sécurité → Chiffrement et identifiants → Installer un certificat → Certificat CA

Ne partagez que sentinel-x-ca.crt : c'est un certificat public. La clé privée de l'autorité ne quitte jamais le volume Docker pki.

5.2 Se connecter en administrateur

Récupérez le mot de passe généré pour l'administrateur initial (admin@sentinel-x.local par défaut) :

docker compose exec backend cat /run/sentinel/secrets/initial-admin-password

Ouvrez https://192.168.10.1 (ou https://localhost sur le serveur) et connectez-vous.

5.3 Créer les comptes des opérateurs

docker compose exec backend node dist/cli/create-user.js operateur@aethercorp.fr "Prénom Nom"

Le mot de passe (12 caractères minimum) est demandé deux fois, sans affichage. Créez un compte nominatif par personne : chaque commande et chaque modification de paramètre est journalisée avec l'e-mail de son auteur.

6 Brancher le matériel

Le matériel se branche à chaud, avant ou après le démarrage, sans aucune configuration :

  • Boîtier ESP8266 : branchez-le en USB. Le service bridge détecte l'unique port USB série (/dev/ttyUSB* ou /dev/ttyACM*) et transmet les mesures en MQTTS. Débranchement et rebranchement sont gérés automatiquement.
  • Webcam : branchez-la en USB, puis cliquez sur Démarrer la webcam dans la page Caméra du dashboard. Si plusieurs caméras sont présentes, indiquez VISION_CAMERA_INDEX dans .env.
docker compose logs -f bridge     # « Port /dev/ttyUSB0 ouvert » puis « MQTT #… »
docker compose logs -f ai         # état de la webcam et des analyses

Les conteneurs n'ont accès qu'aux classes de périphériques nécessaires : ports série pour bridge, caméras vidéo pour ai, selon des règles de cgroup. Aucun conteneur n'est privilégié.

8 Mesures de sécurité

LiaisonProtocoleAuthentification
Navigateur → nginxHTTPS, TLS 1.2/1.3, HSTS ; HTTP redirigéSession Better Auth (cookie __Secure-, HttpOnly, Secure)
nginx → backendHTTPS, certificat vérifié par la CARéseau interne, IP client de confiance limitée à nginx
backend → mosquittoMQTTS (TLS), nom d'hôte vérifiéCompte backend, ACL lecture télémétrie / écriture commandes
bridge → mosquittoMQTTS (TLS), nom d'hôte vérifiéCompte bridge, ACL écriture télémétrie uniquement
backend → aiHTTPS, certificat vérifiéJeton Bearer partagé
ESP8266 → bridgeUSB localAccès physique au serveur
  • Cryptographie : clés ECDSA P-256 ; suites ECDHE avec AES-GCM ou ChaCha20 ; TLS 1.0/1.1 refusés ; certificats de 397 jours renouvelés automatiquement.
  • Secrets : générés aléatoirement (96 bits pour le mot de passe administrateur initial, 192 à 256 bits pour les autres), un propriétaire par fichier, permissions 0400, lus via des variables *_FILE. Ils n'apparaissent ni dans le dépôt, ni dans .env, ni dans docker inspect. Seul un mot de passe SMTP saisi dans .env est passé en variable d'environnement : réservez .env à l'administrateur (chmod 600 .env).
  • Conteneurs : utilisateurs non-root distincts, système de fichiers en lecture seule, toutes les capacités Linux retirées, no-new-privileges, journaux limités (3 × 10 Mo).
  • Réseau : broker, IA et passerelle sur un réseau interne sans accès Internet ; backend et IA non publiés.
  • Application : inscription publique désactivée, mots de passe de 12 caractères minimum, 5 tentatives de connexion par minute et par IP, origines vérifiées. Côté nginx : limites de débit et de connexions par IP, CSP stricte, X-Frame-Options: DENY, nosniff.

9 Durcir le serveur

Docker protège les services ; le système hôte doit l'être aussi. Ces réglages s'appliquent une fois, en gardant une session ouverte pendant les tests SSH.

  1. SSH par clé uniquement : copiez votre clé (ssh-copy-id), vérifiez la connexion, puis dans /etc/ssh/sshd_config : PasswordAuthentication no et PermitRootLogin no, puis sudo systemctl restart ssh.
  2. Pare-feu : 
    sudo apt install ufw
sudo ufw default deny incoming
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
  3. Mises à jour : sudo apt install unattended-upgrades.

Les ports publiés par Docker contournent les règles UFW. La protection repose donc d'abord sur le fait que le Compose ne publie que 80 et 443, et Mosquitto uniquement sur 127.0.0.1. N'ajoutez pas de port publié sans en mesurer l'exposition.

10 Exploiter

Supervision

docker compose ps                    # état et santé des services
docker compose logs -f backend       # journal d'un service
docker stats                         # CPU et mémoire en temps réel

Mettre à jour

git pull
docker compose up -d --build

Les données, comptes, certificats et secrets sont conservés dans les volumes.

Sauvegarder et restaurer

VolumeContenu
sentinel-x_backend-dataComptes, historique des mesures et des analyses, paramètres
sentinel-x_ai-state / sentinel-x_ai-facesModèle d'anomalies entraîné / catalogue facial (données biométriques)
sentinel-x_pki / sentinel-x_secretsAutorité de certification et secrets
 
# Sauvegarde à froid d'un volume
docker compose stop
docker run --rm -v sentinel-x_backend-data:/data:ro -v "$PWD":/backup alpine \
  tar czf /backup/backend-data.tgz -C /data .
docker compose start

Restauration : extraire l'archive dans le volume vide (tar xzf), services arrêtés. Les sauvegardes de pki, secrets et ai-faces sont sensibles : chiffrez-les et stockez-les hors du serveur.

Entraîner le modèle d'anomalies

  1. Exporter les mesures réelles (base en lecture seule) : 
    mkdir -p entrainement
docker compose run --rm --no-deps -u root \
  -v sentinel-x_backend-data:/backend-data:ro -v "$PWD/entrainement":/export \
  ai python -m app.integrations.backend_client \
  --database /backend-data/telemetry.db --output /export/sensor_data.csv
  2. Sélectionner les périodes normales dans entrainement/normal_validated.csv (voir le guide IA).
  3. Entraîner, puis recharger le service : 
    docker compose run --rm --no-deps \
  -v "$PWD/entrainement/normal_validated.csv":/import/normal.csv:ro \
  ai python -m app.anomaly.trainer --csv /import/normal.csv \
  --output /app/state/isolation_forest.joblib
docker compose restart ai

Régénérer les secrets

En cas de compromission : docker compose down, puis docker volume rm sentinel-x_secrets (et sentinel-x_pki pour changer d'autorité), et enfin docker compose up -d. Toutes les sessions sont invalidées. Les comptes existants sont conservés, et le nouveau mot de passe administrateur ne s'applique qu'à une base de comptes vide. Après un changement de CA, réinstallez sentinel-x-ca.crt sur les postes.

11 Windows et macOS

Docker Desktop fonctionne avec la même commande, mais ne transmet ni l'USB ni la webcam aux conteneurs. Le dashboard, le backend, le broker et l'analyse IA des capteurs fonctionnent ; la vision indique « Webcam introuvable ». Pour le boîtier, lancez la passerelle sur l'hôte en MQTTS :

# Mot de passe du compte bridge
docker compose run --rm --no-deps --entrypoint cat init /run/sentinel/secrets/mqtt-bridge-password > bridge-password.txt

.\ai\.venv\Scripts\python.exe scripts\esp_serial_bridge.py --mqtt-host localhost --mqtt-port 8883 `
  --mqtt-ca deploy\runtime\sentinel-x-ca.crt --mqtt-username bridge --mqtt-password-file bridge-password.txt

Protégez bridge-password.txt (droits limités à votre compte) et arrêtez le service bridge du Compose (docker compose stop bridge), inutile dans ce cas. Pour la vision en production, utilisez un serveur Linux.
