1 Rôle du serveur

Le serveur iot-backend est le cœur de la plateforme Sentinel-X. Il fonctionne sur le PC Serveur Local et assure les fonctions suivantes :

  • il reçoit les mesures du boîtier par le broker MQTT et les enregistre (7 jours par défaut) ;
  • il protège l'accès au dashboard par identifiant et mot de passe ;
  • il transmet les mesures au service IA et relaie la vidéo de la webcam ;
  • il envoie les alertes par e-mail (intrusion, visage inconnu, boîtier hors ligne).

Le dashboard web s'adresse uniquement à ce serveur. Si le serveur est arrêté, plus rien ne s'affiche ; le boîtier, lui, continue de déclencher ses alarmes locales.

2 Installation

Windows (recommandé pour le workshop)

Ouvrez PowerShell à la racine du projet et lancez :

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1

Le script installe les dépendances du backend et du dashboard, crée l'environnement Python de l'IA et prépare les fichiers .env manquants à partir des exemples. Il génère aussi le secret de session sans l'afficher. Il ne modifie pas une configuration existante et ne démarre aucun service.

macOS ou Linux

bash install.sh

Le script vérifie Node.js, installe Mosquitto (Homebrew sur macOS) et les dépendances npm. Sous Linux, installez d'abord Node.js, npm et Mosquitto avec le gestionnaire de paquets du système.

Docker (production)

docker compose up -d --build

Cette commande déploie toute la plateforme en HTTPS (broker, service IA et passerelle USB compris), avec certificats et secrets générés automatiquement. Le dashboard est servi sur https://localhost. Toutes les étapes (certificat à installer, mot de passe administrateur, comptes) sont dans le guide de déploiement. Les sections suivantes concernent surtout une installation manuelle ou de développement.

3 Configuration

La configuration se trouve dans iot-backend/.env, créé à partir de iot-backend/.env.example. Les valeurs par défaut conviennent à une installation locale. Seul le secret de session est obligatoire.

  1. Si le script d'installation ne l'a pas fait, générez un secret aléatoire : 
    node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
  2. Collez-le dans BETTER_AUTH_SECRET=. Ne le partagez jamais et ne le versionnez pas.
  3. Pour accéder au dashboard depuis un autre poste du réseau de table, ajoutez son adresse à FRONTEND_ORIGINS et à BETTER_AUTH_URL, par exemple http://192.168.10.1:5173.
ParamètreÀ modifier quand…
MQTT_URLle broker n'est pas sur la même machine ou utilise un autre port
AI_SERVICE_URLle service IA utilise un autre port, ou pour le désactiver (valeur vide)
AI_SERVICE_TOKENvous protégez le service IA par un jeton (même valeur dans ai/.env)
READINGS_RETENTION_DAYSvous souhaitez conserver l'historique plus ou moins longtemps
SMTP_*, MAIL_FROMvous activez l'envoi des alertes par e-mail (section 7)

Changer BETTER_AUTH_SECRET déconnecte tous les utilisateurs. Toute modification de .env nécessite de redémarrer le serveur.

4 Comptes opérateurs

Pour des raisons de sécurité, l'inscription depuis le dashboard est désactivée. Créez chaque compte depuis le dossier iot-backend :

npm run user:create -- operateur@aethercorp.fr "Prénom Nom"

Le mot de passe est demandé deux fois, sans affichage, et doit contenir au moins 12 caractères. Sous Docker, un administrateur initial est créé automatiquement au premier démarrage (voir le guide de déploiement) ; les autres comptes se créent ainsi :

docker compose exec backend node dist/cli/create-user.js operateur@aethercorp.fr "Prénom Nom"
  • Une session dure 8 heures ; l'opérateur doit ensuite se reconnecter.
  • Après 5 tentatives de connexion échouées en une minute depuis une même adresse, les connexions sont bloquées pendant une minute.
  • Chaque commande LED et chaque modification des paramètres sont enregistrées dans le journal avec l'e-mail de l'opérateur.

5 Démarrer et arrêter

Démarrez les services dans cet ordre, chacun dans son propre terminal ouvert à la racine du projet :

  1. Broker MQTT (s'il n'est pas déjà lancé comme service) : 
    & 'C:\Program Files\mosquitto\mosquitto.exe' -c .\scripts\mosquitto-local.conf -v
  2. Serveur iot-backend : 
    Set-Location .\iot-backend
node --env-file=.env --import tsx src/main.ts
    Attendez « HTTP server listening on http://localhost:3001 » puis « Connected to MQTT broker ».
  3. Service IA (facultatif, voir le guide IA) : 
    Set-Location .\ai
.\.venv\Scripts\python.exe -m app.main
  4. Dashboard : 
    Set-Location .\iot-frontend
npm.cmd run dev -- --host 127.0.0.1
  5. Passerelle USB du boîtier (voir le guide du firmware).

Pour arrêter un service, appuyez sur Ctrl+C dans son terminal. Le serveur ferme proprement ses connexions et ses bases.

Sous macOS/Linux, bash run.sh lance d'un coup un mode de test sans boîtier (broker, serveur, dashboard et simulateur), et bash stop.sh l'arrête. Ce mode publie des données simulées : ne l'utilisez pas pendant une validation avec le vrai matériel.

7 Activer les e-mails

Renseignez les paramètres de votre serveur d'envoi dans iot-backend/.env, puis redémarrez :

SMTP_HOST=smtp.exemple.fr
SMTP_PORT=587
SMTP_SECURE=false          # true pour le port 465 (TLS implicite)
SMTP_USER=sentinel@exemple.fr
SMTP_PASSWORD=mot-de-passe-applicatif
MAIL_FROM=SENTINEL-X <sentinel@exemple.fr>

Le chiffrement STARTTLS est exigé sur le port 587. Ensuite, l'adresse de réception se règle dans le dashboard, onglet Paramètres, par un opérateur connecté. Le bouton Envoyer un e-mail de test confirme la configuration.

Sans serveur SMTP, aucun e-mail ne part et la page Paramètres l'indique. En mode test (run.sh), les e-mails sont écrits sous forme de fichiers .eml dans .runtime/mail/, lisibles avec n'importe quel client mail.

Pour éviter le spam, un même type d'alerte est envoyé au plus une fois toutes les 5 minutes.

8 Gérer les données

FichierContenu
iot-backend/data/auth.dbComptes et sessions des opérateurs
iot-backend/data/telemetry.dbHistorique des mesures et des analyses IA
iot-backend/data/settings.dbParamètres des notifications
  • Sauvegarde : arrêtez le serveur puis copiez le dossier data/ ; ou, à chaud, utilisez sqlite3 data/telemetry.db ".backup sauvegarde.db". Sous Docker, les bases sont dans le volume backend-data.
  • Rétention : les mesures et analyses plus anciennes que READINGS_RETENTION_DAYS (7 jours) sont supprimées automatiquement chaque heure.
  • Confidentialité : ces fichiers sont ignorés par Git ; ne les ajoutez jamais au dépôt.
  • Export pour l'IA : le service IA lit telemetry.db en lecture seule pour exporter uniquement les mesures réelles (voir le guide IA).

9 Mode démonstration

Sans boîtier, le simulateur publie des mesures cohérentes (dérive de température, pic de gaz toutes les 4 minutes, passage d'une personne 20 s par minute) et une caméra factice :

npm --prefix iot-backend run simulate

Toutes ses données portent la mention simulation. Elles apparaissent dans les graphiques et l'historique, mais ne modifient pas l'état réel du boîtier et ne déclenchent aucune notification. Arrêtez toujours le simulateur avant de brancher le vrai boîtier, pour ne pas mélanger les sources.
