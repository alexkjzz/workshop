1 Avant de commencer

Le déploiement est automatisé : certificats TLS, mots de passe et clés sont générés par la plateforme elle-même au premier démarrage. Vous n'avez aucun secret à saisir ni à recevoir. Réunissez seulement :

ÉlémentPourquoi
Un accès SSH au serveur avec un compte sudoInstallation de Docker et du pare-feu
L'adresse IP fixe du serveur sur le réseau de la table (ex. 192.168.10.1) et, si prévu, son nom DNSInscrite dans le certificat HTTPS ; les postes utiliseront cette adresse
Un accès Internet pendant l'installationTéléchargement de Docker, des images et des modèles IA. Ensuite, le serveur fonctionne hors ligne
10 Go d'espace disque libre, 4 Go de RAM minimumL'image du service IA pèse environ 2,7 Go
Le boîtier ESP8266 déjà flashé, un câble USB de données, la webcam USBBranchés à l'étape 9

Facultatif : un relais SMTP joignable depuis le serveur (hôte, port, identifiants)Notifications par e-mail

Dans ce document, remplacez 192.168.10.1 par l'adresse réelle du serveur. Les commandes sont à exécuter sur le serveur, dans le dossier /opt/sentinel-x à partir de l'étape 4.

2 Préparer le serveur

  1. Mettre le système à jour : 
    sudo apt update && sudo apt full-upgrade -y
sudo apt install -y git curl
  2. Installer Docker (script officiel, inclut le plugin docker compose) : 
    curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
    Déconnectez-vous puis reconnectez-vous en SSH pour que l'appartenance au groupe docker soit prise en compte.
  3. Contrôler l'installation : 
    docker --version
docker compose version
docker run --rm hello-world

    Attendu : Docker 24 ou plus, Compose v2, et le message « Hello from Docker! ».

  4. Vérifier que les ports 80 et 443 sont libres : 
    sudo ss -ltnp | grep -E ':(80|443) '

    Attendu : aucune ligne. Si un serveur web (Apache, nginx…) répond, arrêtez-le et désactivez-le (sudo systemctl disable --now apache2).

3 Sécuriser le serveur

À faire avant d'exposer le service. Gardez une session SSH ouverte pendant toute cette étape pour ne pas perdre l'accès.

  1. SSH par clé uniquement. Depuis votre poste : ssh-copy-id utilisateur@192.168.10.1, puis vérifiez dans un second terminal que la connexion par clé fonctionne. Ensuite, sur le serveur : 
    sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/; s/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo systemctl restart ssh
  2. Pare-feu : seuls SSH, HTTP (redirection) et HTTPS sont ouverts. 
    sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose
  3. Mises à jour de sécurité automatiques : 
    sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades

Les ports publiés par Docker contournent les règles UFW. La plateforme ne publie que 80 et 443 (et le broker MQTT sur 127.0.0.1 uniquement). Ne modifiez pas les ports publiés dans docker-compose.yml sans accord de l'équipe de développement.

4 Récupérer le code

sudo mkdir -p /opt/sentinel-x
sudo chown $USER:$USER /opt/sentinel-x
git clone https://github.com/alexkjzz/workshop.git /opt/sentinel-x
cd /opt/sentinel-x
git log --oneline -1

Attendu : le dernier commit de main. Notez son identifiant (7 caractères) dans la fiche de recette : il sert au retour arrière.

5 Configurer

Un seul fichier, .env, et uniquement des valeurs non secrètes. Partez du modèle :

cp .env.example .env
chmod 600 .env
nano .env

Modifiez au minimum :

VariableValeur à mettre
PUBLIC_HOSTSL'IP du serveur et, s'il existe, son nom, séparés par des virgules : 192.168.10.1,sentinel-x.local. Obligatoire pour accéder au dashboard depuis les autres postes.
ADMIN_EMAILL'e-mail du premier administrateur. Il n'a pas besoin d'exister : c'est l'identifiant de connexion.

Facultatif : SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, MAIL_FROM pour les notifications par e-mail. Laissez les autres valeurs par défaut.

N'ajoutez aucun mot de passe, clé ou certificat dans .env en dehors de SMTP_PASSWORD : ils sont générés automatiquement. Ne commitez jamais .env (il est ignoré par git).

6 Construire et démarrer

docker compose up -d --build

La première construction dure 20 à 40 minutes sur un Raspberry Pi 5 (surtout l'image IA). Les suivantes ne prennent que quelques secondes. Si la construction s'interrompt sur une erreur réseau (« Read timed out »), relancez simplement la même commande : les téléchargements déjà faits sont en cache.

Au premier lancement, le service init crée l'autorité de certification locale, un certificat par service et tous les secrets, puis s'arrête. Suivez-le :

docker compose logs init

Attendu : « PKI et secrets prets. » puis la ligne « Premier demarrage : compte administrateur … ».

7 Vérifier le déploiement

  1. État des services (attendez une minute après le démarrage) : 
    docker compose ps -a
    ServiceÉtat attendu
    initExited (0) — normal, il ne tourne qu'au démarrage
    frontend, backend, aiUp (healthy)
    mosquitto, bridgeUp
  2. Redirection HTTP vers HTTPS : 
    curl -sI http://192.168.10.1/ | grep -iE "^HTTP|^location"

    Attendu : 301 Moved Permanently et Location: https://192.168.10.1:443/.

  3. Certificat HTTPS valide pour l'adresse du serveur : 
    curl -s --cacert deploy/runtime/sentinel-x-ca.crt https://192.168.10.1/api/health

    Attendu : {"status":"ok"}. Une erreur « certificate » signifie que l'adresse n'est pas dans PUBLIC_HOSTS (étape 5).

  4. API protégée : 
    curl -s -o /dev/null -w "%{http_code}\n" --cacert deploy/runtime/sentinel-x-ca.crt https://192.168.10.1/api/readings

    Attendu : 401 (accès refusé sans connexion).

  5. Services internes non exposés : 
    sudo ss -ltnp | grep -E ':(3001|8001|8883) '

    Attendu : uniquement 127.0.0.1:8883 (broker en local). Ni 3001 ni 8001.

  6. Aucune erreur dans les journaux : 
    docker compose logs backend ai mosquitto | grep -iE "error|fatal"

    Attendu : aucune ligne. Un avertissement joblib « Read-only file system » est normal.

8 Ouvrir l'accès

8.1 Distribuer le certificat de l'autorité

Le fichier /opt/sentinel-x/deploy/runtime/sentinel-x-ca.crt doit être installé sur chaque poste qui ouvrira le dashboard ; sinon, le navigateur affiche un avertissement. Récupérez-le depuis votre poste :

scp utilisateur@192.168.10.1:/opt/sentinel-x/deploy/runtime/sentinel-x-ca.crt .
SystèmeInstallation
WindowsDouble-clic → Installer le certificat → Ordinateur local → « Autorités de certification racines de confiance »
macOSDouble-clic → Trousseau Système → ouvrir le certificat → Se fier : « Toujours approuver »
Linux (Chrome)Paramètres → Confidentialité et sécurité → Gérer les certificats → Autorités → Importer
FirefoxParamètres → Vie privée et sécurité → Certificats → Autorités → Importer

Ce fichier est public : il peut être envoyé par e-mail ou clé USB. La clé privée de l'autorité reste dans le volume Docker du serveur et n'est jamais à transmettre.

8.2 Première connexion administrateur

docker compose exec backend cat /run/sentinel/secrets/initial-admin-password

Ouvrez https://192.168.10.1 depuis un poste équipé du certificat, connectez-vous avec ADMIN_EMAIL et ce mot de passe. Enregistrez immédiatement le mot de passe dans le gestionnaire de mots de passe de l'équipe ; ne l'envoyez pas en clair par messagerie.

8.3 Créer les comptes des opérateurs

Un compte nominatif par personne (les actions sont journalisées avec l'e-mail de leur auteur) :

docker compose exec backend node dist/cli/create-user.js prenom.nom@aethercorp.fr "Prénom Nom"

Le mot de passe (12 caractères minimum) est demandé deux fois, sans affichage. Transmettez-le à la personne par un canal séparé de son identifiant.

9 Brancher le matériel

Le matériel se branche à chaud, sans configuration.

  1. Boîtier ESP8266 : branchez-le en USB avec un câble de données, puis : 
    ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null
docker compose logs -f bridge

    Attendu : un périphérique /dev/ttyUSB0 (ou ttyACM0), puis dans les logs « MQTTS connecte », « Port /dev/ttyUSB0 ouvert » et des lignes « MQTT #… ». Quittez avec Ctrl+C. Les mesures apparaissent sur la page Metrics du dashboard.

  2. Webcam : branchez-la, vérifiez ls /dev/video*, puis dans le dashboard, page Caméra, cliquez sur Démarrer la webcam. Si plusieurs caméras sont détectées et que la mauvaise s'affiche, mettez VISION_CAMERA_INDEX=1 (ou 2…) dans .env puis docker compose up -d.

10 Sauvegarde initiale

Sauvegardez l'autorité de certification et les secrets dès maintenant : sans eux, une réinstallation obligerait à redistribuer un nouveau certificat sur tous les postes.

cd /opt/sentinel-x
docker compose stop
docker run --rm -v sentinel-x_pki:/pki:ro -v sentinel-x_secrets:/secrets:ro \
  -v "$PWD":/backup alpine tar czf /backup/sentinel-x-pki-secrets.tgz /pki /secrets
docker compose start
gpg -c sentinel-x-pki-secrets.tgz && shred -u sentinel-x-pki-secrets.tgz

Stockez sentinel-x-pki-secrets.tgz.gpg hors du serveur (coffre de l'équipe) et la phrase de passe GPG séparément. Les données métier (volume sentinel-x_backend-data) se sauvegardent de la même façon, à fréquence régulière.

Retour arrière

Les données, comptes, certificats et secrets sont dans des volumes Docker : changer de version du code ne les efface pas.

cd /opt/sentinel-x
git checkout <commit-précédent>
docker compose up -d --build

N'utilisez jamais docker compose down -v ni docker volume rm en production : l'option -v supprime définitivement les données, les comptes, l'autorité de certification et les secrets.

Mises à jour ultérieures

cd /opt/sentinel-x
git checkout main      # revient sur la branche après un retour arrière
git pull
docker compose up -d --build
docker compose ps -a

Escalade vers l'équipe de développement

Transmettez l'étape en échec, le commit déployé et ce rapport (il ne contient aucun secret) :

{ git log --oneline -1; docker compose ps -a; docker compose logs --tail 200; } > rapport-incident.txt 2>&1

N'envoyez jamais le contenu de /run/sentinel/secrets, ni le fichier .env s'il contient un mot de passe SMTP.
