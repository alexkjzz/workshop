1 Le boîtier en bref

Le boîtier Sentinel-X surveille une zone sans présence humaine permanente. Il mesure en continu :

  • la température et l'humidité (capteur DHT22) ;
  • la présence de gaz ou de fumée (capteur MQ-2) ;
  • les mouvements dans la zone (détecteur infrarouge PIR).

Il réagit seul, même sans réseau : en cas de gaz ou de mouvement, la LED rouge s'allume et le buzzer sonne. Son écran affiche en permanence les mesures et l'état du système. Relié par USB au PC serveur, il transmet ses mesures au dashboard web grâce à une petite application appelée passerelle USB.

Le boîtier ne reçoit aucun ordre du PC : les boutons « LED » du dashboard n'agissent pas sur cette version du firmware. Les alarmes sont toujours décidées localement par le boîtier.

2 Avant de commencer

Matériel

  • Boîtier Sentinel-X assemblé (NodeMCU ESP8266, DHT22, MQ-2, PIR, écran OLED, 3 LEDs, buzzer)
  • Câble micro-USB de données (certains câbles ne font que charger)
  • PC serveur Windows, macOS ou Linux

Logiciels

  • PlatformIO (extension VS Code ou ligne de commande pio)
  • Python 3.12 avec l'environnement ai/.venv créé par le script d'installation
  • Mosquitto (broker MQTT local), backend et dashboard démarrés

Vérifiez le câblage avant la première mise sous tension. Le tableau ci-dessous reprend le brochage par défaut :

3 Installer le firmware

  1. Fermez tout programme qui utilise déjà le port USB de la carte : moniteur série, Arduino IDE ou passerelle USB.
  2. Branchez la carte au PC avec le câble USB.
  3. Depuis la racine du projet, compilez puis téléversez : 
    pio run -d firmware -e nodemcuv2 -t upload
    PlatformIO télécharge automatiquement les bibliothèques au premier lancement, puis trouve le port de la carte.
  4. Pour voir les messages du boîtier, ouvrez le moniteur série (115 200 bauds) : 
    pio device monitor -d firmware
    Vous devez lire DEMARRAGE SENTINEL-X V2, le type de capteur DHT configuré, puis l'état de l'écran (OLED : OK).
  5. Fermez le moniteur avec Ctrl+C avant de lancer la passerelle : un seul programme peut utiliser le port à la fois.

Avec l'extension PlatformIO de VS Code, ouvrez le dossier firmware et utilisez les boutons Upload (flèche) et Serial Monitor (prise) de la barre d'état.

4 Mettre en service

À chaque mise sous tension, le boîtier passe par une phase de préparation d'environ une minute. Pendant ce temps, il ne déclenche aucune alarme : c'est normal.

MomentCe qui se passeCe que vous voyez
0 sDémarrage, initialisation de l'écranÉcran « SENTINEL X — SECURITY SYSTEM — BOOTING… »
0 à 60 sPréparation des capteursLED orange allumée, écran « STARTING… », bandeau ...
2 sPremière mesure de température et d'humiditéValeurs affichées en grand sur l'écran
45 sFin de calibration du détecteur de mouvementPIR OK remplace PIR...
60 sFin de chauffe du capteur de gazGAS NORMAL remplace GAS WARM
EnsuiteSurveillance activeLED verte allumée, écran « MONITORING », bandeau OK

Le capteur de gaz MQ-2 a souvent besoin de plusieurs minutes pour se stabiliser complètement après une longue période hors tension. Les premières valeurs peuvent être plus élevées que la normale.

6 LEDs et buzzer

SignalSignificationQue faire ?
VerteSystème prêt, mesures valides, aucune alarmeRien : surveillance normale
OrangePréparation en cours, ou capteur de température en erreurAttendre une minute ; si elle persiste, voir le dépannage (DHT)
Rouge + buzzerMouvement détecté ou gaz au-dessus du seuilConsulter l'écran (MOVE! ou DANGER) et le dashboard

L'alarme s'arrête d'elle-même quand la cause disparaît. Pour le gaz, le boîtier attend que la valeur redescende nettement sous le seuil (550 au lieu de 600) avant de revenir à la normale, afin d'éviter un buzzer intermittent.

Le boîtier est un outil de surveillance de démonstration. Il ne remplace pas un détecteur de gaz ou d'incendie certifié.

7 Envoyer les mesures au dashboard

La passerelle USB lit les messages du boîtier et les transmet au serveur. Le broker MQTT, le backend et le dashboard doivent être démarrés (voir le guide d'utilisation du backend).

  1. Installez une fois les deux dépendances de la passerelle : 
    .\ai\.venv\Scripts\python.exe -m pip install -r scripts\requirements-esp.txt
  2. Si le broker local n'est pas déjà lancé, démarrez-le dans un terminal dédié : 
    mosquitto -c scripts\mosquitto-local.conf -v
  3. Repérez le port de la carte : 
    .\ai\.venv\Scripts\python.exe scripts\esp_serial_bridge.py --list-ports
  4. Lancez la passerelle dans un autre terminal (ajoutez --port COM7 si plusieurs cartes sont branchées) : 
    .\ai\.venv\Scripts\python.exe scripts\esp_serial_bridge.py
  5. Attendez les messages « MQTT connecté », puis « Port COMx ouvert », puis des lignes MQTT #… contenant les mesures.

Sous macOS ou Linux, remplacez .\ai\.venv\Scripts\python.exe par ai/.venv/bin/python et utilisez des / dans les chemins.

La passerelle se reconnecte seule si vous débranchez puis rebranchez la carte, même si Windows lui attribue un autre numéro de port. Arrêtez-la avec Ctrl+C avant de rouvrir le moniteur série.

8 Vérifier le bon fonctionnement

  1. Démarrage : après une minute, la LED verte est allumée et l'écran affiche « MONITORING ».
  2. Mesures cohérentes : comparez la température et l'humidité affichées avec un thermomètre de référence.
  3. Mouvement : passez devant le détecteur. La LED rouge s'allume, le buzzer sonne, l'écran affiche MOVE!.
  4. Transmission : dans le dashboard, page Métriques, le panneau « État du boîtier ESP » affiche « Mouvement détecté » et « Alarme locale : Active ».
  5. Retour au calme : quelques secondes après votre départ, tout revient au vert.
  6. Coupure : débranchez l'USB. Après 30 secondes, le dashboard indique des états inconnus ; rebranchez, les mesures reprennent.
